OBJETIVO
--------

Un estudiante nuevo debe poder crear su recorrido mediante:

A) Subir un certificado analitico PDF generado por SIU Guarani.
B) Seleccionar carrera/plan y comenzar una carga manual.

El flujo debe persistir los datos y terminar en /dashboard.

La prueba interna esta limitada a Diseno Multimedial, pero la arquitectura
debe contemplar:

- Licenciatura en Diseno Multimedial.
- Profesorado en Diseno Multimedial.
- Distintos planes de estudio.

No asumir que Diseno Multimedial es una unica carrera.

Antes de implementar inspeccionar:

- profiles.degree
- profiles.curriculum
- subjects.curriculum

No cambiar el esquema Supabase. Si existen valores legacy como old/new,
crear mapping TypeScript y separar siempre valor interno de label visible.


RUTA Y FLUJO DE ONBOARDING
--------------------------

Crear /onboarding.

Debe estar disponible solo para usuarios autenticados.
Si un usuario ya tiene carrera/plan y recorrido cargado, no repetirlo.
No impedir que luego importe o edite desde /dashboard/recorrido.

Pantalla inicial:

    Armemos tu recorrido

    Podes subir tu analitico o empezar marcando las materias a mano.

Mostrar dos caminos:

1. SUBIR MI ANALITICO
   Label: Mas rapido

2. CARGAR A MANO

Ninguna opcion debe ser irreversible.
Mostrar:

    Despues podes modificar todo desde Recorrido.


CAMINO A - ANALITICO PDF
------------------------

El usuario no debe elegir carrera/plan obligatoriamente antes de subir.
El PDF debe intentar detectar carrera y plan.

Flujo:

Seleccionar PDF -> Procesando -> Resultado -> Confirmacion de carrera/plan
-> Revision de materias -> Guardar -> Dashboard.

Aceptar inicialmente solamente PDF generado por SIU Guarani.
No prometer imagenes ni aceptar JPG/PNG como si existiera OCR.

Microcopy:

    Subi el PDF de tu analitico
    Por ahora funciona con el certificado PDF generado por SIU Guarani.

Reutilizar app/api/parse-analitico/route.ts y PDF.js existente.
Separar el parsing de la API HTTP cuando sea posible.

Crear preferentemente:

    lib/academic/analytic-parser.ts

Tipos conceptuales:

    type ParsedAnalytic = {
      detectedDegree: ...
      detectedCurriculum: ...
      subjects: ParsedAnalyticSubject[]
      reportedApprovedCount?: number
      reportedAverage?: number
      reportedProgress?: number
      warnings: string[]
    }

    type ParsedAnalyticSubject = {
      rawName: string
      grade?: number
      passedAt?: string
      recordNumber?: string
    }

No devolver ni persistir:

- DNI.
- Codigo de validacion.
- Nombre completo.
- Otros identificadores personales innecesarios.

No copiar el PDF real usado durante el desarrollo al repositorio.
No agregarlo a fixtures.
No incluir datos personales en tests.
Si se necesitan fixtures, usar datos ficticios y estructura sintetica.


PARSER Y FILAS MULTILINEA
-------------------------

El documento puede contener:

    FACULTAD DE ARTES
    PROFESORADO EN DISENO MULTIMEDIAL
    Plan: 2006

Luego:

    Aprobadas
    Asignatura
    Nota
    Fecha
    Acta/Resolucion

Los nombres pueden estar partidos en varias lineas. No asumir una linea por
materia.

Ejemplo conceptual:

    Identidad, Estado y Sociedad en Latinoamerica y
    Argentina 8 (Ocho) 17/12/2022 12345

La nota puede ser 8 (Ocho), la fecha DD/MM/YYYY y el acta puede aparecer al
final.

Extraer, si existen:

- Promedio academico.
- Total de asignaturas aprobadas.
- Porcentaje de avance.

Usarlos solamente para validar la importacion. El progreso oficial debe
seguir calculandose desde subjects y user_subjects.


NORMALIZACION Y MATCHING
------------------------

Crear normalizeSubjectName(name), normalizando:

- lowercase;
- trim;
- espacios multiples;
- acentos;
- puntuacion irrelevante.

No modificar el nombre mostrado al usuario.

Comparar materias con subjects del plan detectado y clasificar:

- EXACT
- PROBABLE
- UNMATCHED

EXACT puede venir preseleccionado.
PROBABLE requiere confirmacion.
UNMATCHED permite elegir materia manualmente o ignorar.

No guardar fuzzy matches dudosos.
No inventar materias nuevas desde el navegador.


PANTALLA DE REVISION
--------------------

Debe mostrar:

- Carrera detectada.
- Plan detectado.
- Cantidad extraida.
- Cantidad reconocida.
- Cantidad que necesita revision.

Cada fila muestra:

- Nombre.
- Estado.
- Nota.
- Fecha.

Ejemplo:

    Tecnologia Multimedial I
    APROBADA - 10
    20 dic 2021

Para coincidencias dudosas:

    Nombre del analitico
    Creemos que corresponde a:
    [selector de materia]

Permitir corregir match, ignorar fila y modificar nota.


VALIDACION CRUZADA
------------------

Si el certificado informa reportedApprovedCount, compararlo con la cantidad
extraida.

Si coincide:

    El analitico coincide.

Si no coincide, no bloquear:

    El analitico indica X materias aprobadas, pero pudimos reconocer Y.
    Revisemos las que faltan.

El promedio informado puede compararse con tolerancia de redondeo.
Las discrepancias son warnings, no errores fatales.


GUARDADO
--------

Guardar solamente luego de confirmar la pantalla de revision.

Persistir:

- profiles.degree
- profiles.curriculum
- user_subjects

Usar valores internos compatibles con el esquema actual.

Para materias aprobadas:

    status = approved

Guardar grade y passed_at cuando existan.

Usar upsert o estrategia segura para:

- no crear duplicados;
- no borrar progreso existente;
- no empeorar datos corregidos manualmente.

Inspeccionar y reutilizar las convenciones existentes de MateriasManager.
