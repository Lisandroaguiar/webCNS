MESITA VIRTUAL — INFORME SPRINT 3
Datos académicos oficiales: agenda y horarios de cátedras

1. RESUMEN FUNCIONAL

Se implementó la base server-side para descubrir, importar, normalizar, revisar
y publicar datos oficiales de la Facultad de Artes UNLP.

El flujo es:

fuente oficial → adapter → parser → normalización → draft en Supabase →
revisión administrativa → publicación → lectura pública en Mesita.

Se actualizaron:

- /agenda para leer academic_events publicados;
- AcademicDeadlineCard para mostrar el próximo evento y su fuente;
- /catedras para mostrar horarios publicados junto a contactos existentes;
- /dashboard para mostrar el próximo evento publicado;
- /admin/imports para ejecutar imports y revisar drafts.

No se implementaron Web Push, Service Worker/PWA, emails, OCR, nuevas
correlatividades ni soporte para carreras fuera de Diseño Multimedial.

6. MÉTODO DE LECTURA DE GOOGLE SHEETS

Se usa fetch server-side sobre la exportación CSV pública, no se automatiza la
interfaz de Google Sheets.

El fetch:

- usa User-Agent identificable;
- sigue redirects;
- tiene timeout de 20 segundos;
- rechaza respuestas mayores a 15 MB;
- calcula SHA-256.

La página índice oficial de Multimedia se utilizó para descubrir y verificar las
URLs actuales. Las URLs se registran en data_sources para poder actualizarlas
sin tocar React.

7. ALGORITMO DE GRILLA HORARIA

El parser detecta la fila de encabezados con los días Lunes a Viernes.
Luego recorre filas cuyo primer campo es una hora HH:MM.

Para cada celda no vacía:

- el nombre de la materia se toma de la primera línea;
- las líneas siguientes se analizan como comisión, aula, sede y notas;
- se genera una fila independiente por día y hora;
- se genera external_key estable usando SHA-256;
- si la duración no está expresada de manera confiable, end_time queda NULL.

Esto soporta nombres y detalles multilínea y no asume una tabla tradicional
materia/día/hora.

8. PARSER DE CALENDARIO

Se reutiliza PDF.js en runtime Node.

El parser:

- detecta el año académico del documento;
- identifica inscripción, mesa/examen y otros eventos;
- procesa rangos del mismo mes;
- procesa rangos entre meses;
- convierte a ISO;
- genera warning si no encuentra año o rangos reconocibles.

Ejemplo cubierto por tests:

- 2 al 8 de noviembre de 2026;
- 30 de noviembre al 5 de diciembre de 2026.

No se hardcodearon las fechas de noviembre o diciembre como lógica del parser.

9. MATCHING CON subjects

Se reutiliza la normalización académica del Sprint 2:

- minúsculas;
- eliminación de acentos;
- puntuación irrelevante;
- espacios normalizados.

La importación intenta igualdad normalizada. Si no coincide, el horario queda
con raw_subject_name y subject_id NULL. No se guarda un fuzzy match ambiguo.

10. STAGING, PUBLICACIÓN Y FUENTES CAÍDAS

Los imports escriben drafts y nunca publican automáticamente.

La pantalla administrativa permite:

- ejecutar un import;
- ver cantidad encontrada, cambiada y warnings;
- publicar un draft;
- descartar un draft, pasándolo a stale.

Una ejecución con cero registros queda como warning. No se borran horarios ni
eventos anteriores automáticamente.

Los registros encontrados actualizan last_seen_at.

11. AUTORIZACIÓN ADMINISTRATIVA

La página /admin/imports y los endpoints verifican sesión server-side y
comparan el email con:

CRONOPIOS_ADMIN_EMAILS

El endpoint no acepta URLs arbitrarias. Solo acepta source keys del registry.

Para escribir datos de importación se usa SUPABASE_SERVICE_ROLE_KEY únicamente
en servidor. Nunca se envía al navegador. Si no está configurada, el endpoint
devuelve un error explícito y no ejecuta el import.

lib/fda/source-registry.ts.
